# Story 6.6: Migration + Snapshot Semanal de Keywords
**Epic:** DESTAKA-EPIC-003 (Dashboard v2)
**Wave:** 2 - Keywords como Insight Automatico
**Tipo:** Backend
**Agente:** @dev
**Status:** Draft
**Prioridade:** P1

## Objetivo
Tabela para armazenar snapshots semanais de keywords de busca e Inngest function para coleta automatica.

## Contexto
O GBPClient ja implementa getSearchKeywords() que busca dados da GBP Performance API. Os dados sao buscados mas nunca armazenados. Precisamos persistir para calcular tendencias (semana vs semana).

## Acceptance Criteria
- [ ] Migration: tabela keyword_snapshots (id uuid, org_id uuid FK, profile_id uuid FK, keyword text, impressions int, clicks int, week_start date, created_at timestamptz)
- [ ] Index: (org_id, week_start) para queries rapidas
- [ ] RLS: usuarios so veem dados da propria org
- [ ] Inngest function keyword-snapshot em src/lib/inngest/functions/keyword-snapshot.ts
- [ ] Cron: toda segunda-feira as 07:00 UTC (apos geo-collector)
- [ ] Itera sobre perfis ativos, chama getSearchKeywords(), armazena top 20 keywords
- [ ] Event trigger manual: destaka/keywords.snapshot.requested
- [ ] Registrada no route.ts do Inngest
- [ ] Migration aplicada no Supabase

## Arquivos a criar/modificar
- supabase/migrations/XXX_keyword_snapshots.sql (novo)
- src/lib/inngest/functions/keyword-snapshot.ts (novo)
- src/app/api/inngest/route.ts (registrar)

## Definition of Done
- Migration aplicada, RLS testado
- Function dispara manualmente e armazena dados
- Logs limpos
