## EPIC-005: Geo Expansion Engine

### Objetivo
Expandir automaticamente o raio de visibilidade do profissional no Google Maps, usando dados geograficos que o Destaka ja coleta semanalmente.

### Premissas
- Expansao geografica e SEMPRE automatica, independente da `automation_preference` do usuario
- Dados de entrada: `geo_snapshots` (zonas forte/media/fraca) + `keyword_snapshots` (impressoes)
- O profissional nao precisa fazer nada. O Destaka executa.

### Fluxo

```
geo-collector (seg 6am) coleta zonas atuais
  |
  v
geo-expansion-engine (seg 8am, novo Inngest function)
  |
  ├── 1. Analisa geo_snapshot atual vs anterior
  │     - Identifica zonas fracas e ausentes
  │     - Calcula direcoes de expansao prioritarias
  │
  ├── 2. Reverse geocoding (Google Geocoding API)
  │     - Coordenadas das zonas alvo → nomes de bairros/regioes
  │
  ├── 3. Executa automaticamente:
  │     a) PATCH service_areas no GBP API com regioes alvo
  │     b) Gera post geo-targeted via Claude (menciona bairro/regiao)
  │     c) Enriquece description do GBP com keywords geograficas
  │
  ├── 4. Salva em geo_expansion_log:
  │     - acoes tomadas, regioes alvo, data
  │
  └── 5. Proxima semana: compara novo snapshot
        - Raio expandiu? Zona fraca virou media/forte?
        - Registra evolucao
```

### Tabela nova: geo_expansion_log

```sql
CREATE TABLE geo_expansion_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID REFERENCES organizations(id) NOT NULL,
  week_start DATE NOT NULL,
  actions_taken JSONB NOT NULL,
  -- [{type: 'service_area', regions: ['Botafogo', 'Flamengo']},
  --  {type: 'post', post_id: '...', region: 'Botafogo'},
  --  {type: 'description', keywords_added: ['dentista botafogo']}]
  target_regions TEXT[] NOT NULL,
  previous_radius_km NUMERIC,
  current_radius_km NUMERIC,
  zones_before INTEGER,
  zones_after INTEGER,
  created_at TIMESTAMPTZ DEFAULT now()
);
```

### Dashboard
- Card "Expansao Geografica" no mapa: raio atual vs 4 semanas atras
- Zonas alvo marcadas em cor diferente (amarelo = em expansao)
- Historico: grafico simples de radius_km ao longo do tempo

### Stories

| # | Story | Estimativa |
|---|-------|------------|
| 1 | Inngest function `geo-expansion-engine` (analise + decisao) | M |
| 2 | Reverse geocoding: coordenadas → nomes de bairros | P |
| 3 | PATCH service_areas no GBP API | P |
| 4 | Post geo-targeted automatico via Claude | M |
| 5 | Description enrichment com keywords geo | P |
| 6 | Migration: tabela `geo_expansion_log` | P |
| 7 | Dashboard: card evolucao do raio | M |
| 8 | Dashboard: zonas alvo no mapa | M |

### Metrica de sucesso
- Aumento de `radius_km` e `total_zonas` em 4-8 semanas
- Aumento de impressoes em keywords geolocalizadas

## EPIC-006: Competitive Intelligence (Onboarding + Interno)

### Objetivo
Usar os dados competitivos ja coletados para acao automatica, sem expor complexidade ao usuario.

### Premissas
- Keywords: inteligencia INTERNA. O usuario NUNCA ve keywords. O Destaka usa internamente para otimizar description, posts e categorias.
- Categorias: oferecidas como checklist no onboarding. O profissional ve as categorias que os concorrentes usam e da check nas que se aplicam.
- Fotos: so pede ao usuario se o Destaka nao conseguir puxar do Instagram dele.

### Componentes

#### 6.1 Onboarding: Checklist de Categorias
- Apos o diagnostico, antes do pagamento (ou durante onboarding pos-pagamento)
- Mostra categorias que os concorrentes top usam e que o profissional nao tem
- Interface: lista com checkboxes, pre-marcadas com as recomendadas
- Ao confirmar: Destaka aplica via GBP API automaticamente
- Fonte: `competitive_analyses.gaps` onde `type = 'categories'`

#### 6.2 Inteligencia Interna de Keywords
- `competitive_analyses.keyword_opportunities` alimenta automaticamente:
  - Posts gerados pelo `post-generator` (inclui keywords naturalmente)
  - Description updates (geo-expansion + keyword enrichment)
  - Score calculator (avalia se keywords alvo estao crescendo)
- NENHUMA dessas keywords aparece pro usuario. E motor interno.

#### 6.3 Fotos: Instagram First
- Fluxo de decisao:
  1. Profissional tem Instagram? (`organizations.instagram_handle`)
  2. Sim → `instagram-sync` puxa fotos → posta no GBP (EPIC-007)
  3. Nao → Onboarding sugere: "Adicione fotos do consultorio ao seu perfil"
  4. Meta de fotos baseada na media dos concorrentes (`competitive_analyses.gaps` onde `type = 'photos'`)

#### 6.4 Benchmark Report (interno)
- `gbp_profiles.benchmark_report` ja existe
- Alimenta o score calculator e o geo-expansion-engine
- NAO exibido ao usuario como painel separado

### Stories

| # | Story | Estimativa |
|---|-------|------------|
| 1 | Onboarding step: checklist de categorias com apply automatico | M |
| 2 | Pipeline interno: keywords → post-generator + description | M |
| 3 | Logica de decisao fotos: Instagram first, fallback pedido manual | P |
| 4 | Integrar benchmark_report no score calculator | P |

## EPIC-007: Instagram → GBP Auto-Publisher

### Objetivo
Completar o pipeline ja existente: puxar conteudo do Instagram do profissional, reescrever com IA, e publicar automaticamente no Google Meu Negocio.

### Premissas
- Direcao: Instagram → GBP (nao o contrario)
- `instagram-sync` ja roda semanalmente e faz scrape + rewrite
- `GBPClient.createPost` ja existe e funciona
- NAO precisa de OAuth da Meta. Scrape ja funciona.

### Fluxo atual (ja implementado)

```
instagram-sync (seg 7am)
  ├── Scrape: busca posts recentes do Instagram do profissional
  ├── Rewrite: Claude reescreve caption para tom profissional
  └── Salva: instagram_posts (status = 'ready', rewritten_caption, image_url)
```

### Fluxo novo (completar o pipeline)

```
instagram-sync (seg 7am)
  ├── [existente] Scrape + Rewrite → instagram_posts (status = 'ready')
  └── [NOVO] Para cada post ready:
      ├── Download da imagem (URL do Instagram)
      ├── Upload para GBP via Media API (ou Supabase Storage como intermediario)
      ├── GBPClient.createPost(locationId, { summary: rewritten_caption, media })
      ├── Atualiza: instagram_posts.status = 'published_gbp'
      └── Atualiza: posts table (registro unificado)
```

### Desafios tecnicos
- Upload de imagem: GBP Local Posts API aceita `mediaItem` com URL publica. O Instagram serve imagens via CDN com URLs temporarias. Pode precisar de intermediario (Supabase Storage ou similar).
- Rate limit: GBP API tem limite de posts por dia. Limitar a 1-2 posts por semana por org.

### Stories

| # | Story | Estimativa |
|---|-------|------------|
| 1 | Download + armazenamento temporario de imagem do Instagram | M |
| 2 | Publicacao no GBP com imagem (GBPClient.createPost + media) | M |
| 3 | Status tracking: instagram_posts.status = 'published_gbp' | P |
| 4 | Rate limit: max 2 posts/semana por org | P |
| 5 | Fallback: se imagem falha, posta so texto | P |

## EPIC-008: Patient Conversion Funnel

### Objetivo
Mostrar ao profissional o funil de conversao real: quantas pessoas te encontraram, quantas viram seu perfil, quantas tomaram acao (ligaram, pediram rota, clicaram no WhatsApp).

### Premissas
- Funil mostra APENAS numeros puros. Sem sugestoes de "faca X para Y".
- O produto automatiza. O usuario colhe resultados.
- Dados vem da GBP Performance API (que o keyword-snapshot ja acessa)
- Exibicao: dashboard + relatorio mensal

### Dados necessarios (GBP Performance API)

| Metrica | Campo API | Posicao no funil |
|---------|-----------|-----------------|
| Impressoes de busca | `QUERIES_DIRECT` + `QUERIES_INDIRECT` | Topo |
| Visualizacoes do perfil | `VIEWS_MAPS` + `VIEWS_SEARCH` | Meio |
| Ligacoes | `ACTIONS_PHONE` | Fundo |
| Rotas | `ACTIONS_DRIVING_DIRECTIONS` | Fundo |
| Cliques no site | `ACTIONS_WEBSITE` | Fundo |

### Dashboard: Card "Seus Pacientes"

```
Esta semana:
  450 pessoas te encontraram no Google
   ↓
  120 viram seu perfil
   ↓
  18 tomaram acao
    ├── 8 ligaram
    ├── 6 pediram rota
    └── 4 clicaram no site

  vs semana passada: +12% impressoes, +3 ligacoes
```

- Sem grafico complexo. Numeros grandes, limpos, com delta semanal.
- Visual: funil vertical simples, numeros em destaque.

### Relatorio mensal
- Secao "Pacientes" adicionada ao monthly-report.ts
- Mesmos dados, agregados mensalmente
- Copy: "Em outubro, 1.800 pessoas encontraram voce no Google. 72 ligaram."

### Stories

| # | Story | Estimativa |
|---|-------|------------|
| 1 | Inngest: coletar metricas de performance semanal (novo ou expandir keyword-snapshot) | M |
| 2 | Migration: tabela `performance_metrics` ou expandir keyword_snapshots | P |
| 3 | API route: /api/dashboard/funnel | P |
| 4 | Dashboard: card "Seus Pacientes" com funil vertical | M |
| 5 | Relatorio mensal: secao pacientes | P |

### Metrica de sucesso
- Profissional entende em 5 segundos quantos pacientes o Destaka trouxe
- Aumento de retencao (profissional ve valor concreto)

## EPIC-009: Review Intelligence no Relatorio Mensal

### Objetivo
Adicionar analise de sentimento e insights dos reviews ao relatorio mensal que ja e enviado. Sem dashboard separado.

### Premissas
- Vai como secao adicional no `monthly-report.ts` existente
- Analise feita pelo Claude no momento da geracao do relatorio
- Dados: `reviews.comment` do mes

Avaliacoes do mes:

## EPIC-010: Smart Alerts

### Objetivo
Alertar o profissional por email quando algo critico acontece. Apenas 2 tipos de alerta.

### Premissas
- Apenas 2 alertas. Nao inflar com notificacoes desnecessarias.
- Canal: email (Resend, ja configurado)
- Reviews 1-3 estrelas: ZERO resposta automatica. Email imediato pro profissional.

### Alerta 1: Review Negativo (1-3 estrelas)

**Trigger:** `review-monitor` detecta review com rating <= 3
**Acao:** Envia email imediatamente (nao espera 6h)
**Template:**

```
Assunto: Avaliacao [rating]★ no seu perfil. Precisa da sua atencao.

[nome do paciente] deixou uma avaliacao de [rating] estrela(s):

"[texto do review]"

Responder pessoalmente a avaliacoes negativas e fundamental.
Pacientes que veem uma resposta cuidadosa do profissional
confiam mais do que se o review negativo nao existisse.

[Botao: Responder agora →]
```

**Importante:** O Destaka NAO gera resposta automatica para reviews 1-3 estrelas. O profissional DEVE responder pessoalmente.

### Alerta 2: Token Google Desconectado

**Trigger:** `getValidGmbToken` falha em qualquer Inngest function
**Acao:** Envia email (max 1 por dia, evita spam)
**Template:**

```
Assunto: Sua conta Google foi desconectada. O Destaka precisa de reconexao.

O Destaka nao esta conseguindo acessar seu perfil no Google.
Isso significa que avaliacoes, posts e otimizacoes estao pausados.

Para reconectar, basta acessar seu painel:

[Botao: Reconectar conta Google →]
```

### Stories

| # | Story | Estimativa |
|---|-------|------------|
| 1 | Email template: review negativo | P |
| 2 | Trigger no review-monitor: if rating <= 3, send email imediato | P |
| 3 | Bloquear auto-resposta para reviews 1-3 estrelas | P |
| 4 | Email template: token desconectado | P |
| 5 | Trigger nas Inngest functions: detectar token failure + enviar email (1/dia max) | P |
| 6 | Migration: tabela `alerts_sent` (dedup, max 1/dia por tipo) | P |

## Dependencias entre EPICs

```
006 (categorias + keywords internas) ──→ 005 (usa keywords no geo expansion)
007 (Instagram → GBP) ──→ 006 (fotos: Instagram first)
008 (funnel) ──→ independente
009 (review intelligence) ──→ independente
010 (alertas) ──→ independente
```

EPICs 008, 009 e 010 podem ser executados em paralelo.
EPIC 006 deve vir antes do 005 (keywords internas alimentam a expansao geo).
EPIC 007 deve vir antes ou junto com 006 (pipeline de fotos depende do publisher).
